- Exactly 23 base tables with identical column structure and business intent.

## 4. Technical Implementation & Data-Type Mappings

### 4.1 Primary Key & Identity Strategy
- All 23 tables utilize: `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`.
- Foreign key columns refer to these as `BIGINT`.
- Explicit IDs can be inserted for seed/fixture data, followed by sequence resynchronization (`setval(pg_get_serial_sequence('roles', 'id'), ...)`).

### 4.2 Integer & Numeric Types
- MySQL `BIGINT UNSIGNED` $\rightarrow$ PostgreSQL `BIGINT`.
- MySQL `INT UNSIGNED` $\rightarrow$ PostgreSQL `INTEGER`. Non-negativity is preserved by CHECK constraints.
- MySQL `DECIMAL(6,2)` $\rightarrow$ PostgreSQL `NUMERIC(6,2)` across `marks.mark_value`, `assessment_applicability.maximum_marks`, and `school_settings.pass_mark`. No float rounding occurs.

### 4.3 Boolean Type
- MySQL `TINYINT(1)` / `BOOLEAN` $\rightarrow$ PostgreSQL native `BOOLEAN` (`is_active`, `is_current`, `is_displayed`).

### 4.4 ENUM Types
Created 8 dedicated PostgreSQL ENUM types:
1. `academic_year_status_enum` (`'open'`, `'closed'`)
2. `subject_category_enum` (`'main'`, `'elective'`)
3. `student_placement_status_enum` (`'active'`, `'internal_transfer'`, `'withdrawn'`, `'transferred_out'`)
4. `assessment_status_enum` (`'active'`, `'inactive'`)
5. `teacher_assignment_type_enum` (`'subject_teacher'`, `'class_teacher'`)
6. `mark_result_status_enum` (`'blank'`, `'numeric'`, `'absent'`)
7. `calculation_method_enum` (`'average_percentage'`, `'combined_marks'`)
8. `report_type_enum` (`'exam'`, `'term'`, `'final'`)

### 4.5 JSON $\rightarrow$ JSONB
- `report_configurations.configuration_data` $\rightarrow$ `JSONB`
- `audit_logs.before_data` $\rightarrow$ `JSONB`
- `audit_logs.after_data` $\rightarrow$ `JSONB`
Enables structured indexing, query operators (`->`, `->>`), and compact binary storage.

### 4.6 Timestamp & `updated_at` Trigger Strategy
- Timestamps use `TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP`.
- PostgreSQL lacks MySQL's inline `ON UPDATE CURRENT_TIMESTAMP`. To provide 100% database-enforced parity on direct updates, a reusable trigger function was created:
  ```sql
  CREATE OR REPLACE FUNCTION trigger_set_updated_at()
  RETURNS TRIGGER AS $$
  BEGIN
      NEW.updated_at = clock_timestamp();
      RETURN NEW;
  END;
  $$ LANGUAGE plpgsql;
  ```
- Attached `BEFORE UPDATE` to all 21 tables containing `updated_at` (every table except the 2 append-only historical tables: `generated_reports` which uses `generated_at`, and `audit_logs` which uses immutable `created_at`). Live testing verified that updating a row advances `updated_at` automatically without manual intervention.

### 4.7 Case-Insensitive Uniqueness Strategy
MySQL's `utf8mb4_unicode_ci` collates case-insensitively. In PostgreSQL, standard unique constraints on text are case-sensitive. To ensure case variants like `admin` and `ADMIN` cannot bypass uniqueness:
- `roles`: `CREATE UNIQUE INDEX uk_roles_name ON roles (LOWER(name));`
- `users`: `CREATE UNIQUE INDEX uk_users_username ON users (LOWER(username));`
- `academic_years`: `CREATE UNIQUE INDEX uk_academic_years_name ON academic_years (LOWER(name));`
- `classes`: `CREATE UNIQUE INDEX uk_classes_name ON classes (LOWER(name));`
- `subjects`: `CREATE UNIQUE INDEX uk_subjects_name ON subjects (LOWER(name));`
- `assessment_types`: `CREATE UNIQUE INDEX uk_assessment_types_name ON assessment_types (LOWER(name));`

### 4.8 Expression-Based Unique Indexes for Nullable Values
1. **`class_subjects` (Class-wide offering uniqueness):**
   ```sql
   CREATE UNIQUE INDEX uk_class_subjects_config
       ON class_subjects (academic_year_id, class_id, (COALESCE(section_id, 0)), subject_id);
   ```
   Prevents duplicate class-wide configurations where `section_id IS NULL`.
2. **`generated_reports` (Historical revision identity):**
   ```sql
   CREATE UNIQUE INDEX uk_gr_revision_identity
       ON generated_reports (student_academic_record_id, report_type, (COALESCE(term_id, 0)), (COALESCE(assessment_id, 0)), revision_number);
   ```
   Prevents duplicate revision numbers across exam, term, and final report contexts where `term_id` or `assessment_id` may be NULL.

## 5. Referential Integrity & CHECK Constraints

### 5.1 Foreign Keys (43 Total)
All 43 foreign keys enforce:
```sql
ON DELETE RESTRICT ON UPDATE RESTRICT
```
No cascading deletes or nullifications exist.

### 5.2 CHECK Constraints (7 Total)
1. `chk_aa_max_marks_positive`: `maximum_marks > 0`
2. `chk_marks_result_consistency`:
   - `result_status = 'numeric' AND mark_value IS NOT NULL AND mark_value >= 0`
   - `result_status = 'blank' AND mark_value IS NULL`
   - `result_status = 'absent' AND mark_value IS NULL`
3. `chk_attendance_days_not_negative`: `days_attended >= 0`
4. `chk_attendance_total_not_negative`: `total_working_days >= 0`
5. `chk_attendance_days_within_total`: `days_attended <= total_working_days`
6. `chk_ta_assignment_subject_consistency`:
   - `assignment_type = 'class_teacher' AND subject_id IS NULL`
   - `assignment_type = 'subject_teacher' AND subject_id IS NOT NULL`
7. `chk_ss_pass_mark_non_negative`: `pass_mark >= 0`

- **Negative Test Enforcement:** All negative tests utilize `assert_negative_sql` with strict comparison between the actual PostgreSQL `SQLSTATE` and the expected `SQLSTATE`. Unexpected error codes or unexpected statement successes trigger immediate test failure.
- **Total Assertions Executed:** 54 (40 core scenarios + 2 PostgreSQL engine extensions: case-insensitive uniqueness and `updated_at` trigger behavior)
- **Passed:** 54
- **Failed:** 0
- **Negative Rejections Expected & Verified:** 18
  - SQLSTATE `23505` (`unique_violation`): Term seq, Roll number, Calc settings, Selection, Report revision, Class-wide NULL offering, Case-insensitive username.
  - SQLSTATE `23514` (`check_violation`): Max marks $\le$ 0, Negative mark, Numeric with NULL, Blank with value, Absent with value, Attendance > total, Class teacher with subject, Subject teacher with NULL.

  - SQLSTATE `22P02` (`invalid_text_representation`): Invalid enum value for calculation method and academic year status.
- **Application Invariants Documented:** 3 (Mark $\le$ max marks, Single current year, Audit log immutability).
